# Enterprise Network Configuration

## Project Description

The project simulates a segmented enterprise LAN in which three departments — **HR**, **IT**, and **GUEST** — are isolated into separate VLANs, each connected through its own access switch to a central **Multilayer Switch**. The multilayer switch performs inter-VLAN routing and also provides access to a shared server farm (DHCP, DNS, and Web) and to a **Core Router**, which represents the edge of the network / connection point toward the outside world.

The purpose of the exercise is to demonstrate VLAN segmentation, trunking between access switches and the multilayer switch, centralized DHCP assignment across multiple VLANs, and inter-VLAN communication controlled by a Layer 3 device, all while keeping each department's traffic logically separated.

---

## Network Topology

### Core Devices

- **Core-Router**, interface `Gig0/0/0`, connected to **Multilayer Switch0** port `Fa0/7`. It represents the network edge and is configured as the default gateway (`192.168.1.1`) for the server segment.
- **Multilayer Switch0** is the central Layer 3 device of the topology. It aggregates all traffic and routes between VLANs. Its relevant ports are:
  - `Fa0/7` → Core-Router (uplink)
  - `Fa0/4` → DHCP Server
  - `Fa0/5` → DNS Server
  - `Fa0/6` → Web Server
  - `Fa0/3` → SW-HR (`Fa0/1`) — trunk carrying **VLAN 10 (HR)**
  - `Fa0/1` → SW-IT (`Fa0/1`) — trunk carrying **VLAN 20 (IT)**
  - `Fa0/2` → SW-GUEST (`Fa0/1`) — trunk carrying **VLAN 30 (GUEST)**

### Server Farm

All three servers sit on the same `192.168.1.0/24` segment, directly attached to the multilayer switch, with the Core-Router's `Gig0/0/0` interface (`192.168.1.1`) acting as their default gateway:

| Server | Interface | IP Address | Role |
|---|---|---|---|
| DHCP Server | Fa0 | 192.168.1.2 | Issues IP leases for VLAN 10, VLAN 20, and VLAN 30 |
| DNS Server | Fa0 | 192.168.1.3 | Resolves `www.yourcompany.com` |
| Web Server | Fa0 | 192.168.1.4 | Hosts the corporate web page |

### Access Layer — VLANs

Each department has its own access switch, connected with a single uplink (trunk) to the multilayer switch, and hosts three client laptops on access ports:

**VLAN 10 – HR (SW-HR)**
- `Fa3/1` → Laptop0 (`Fa0`)
- `Fa2/1` / `Fa1/1` → Laptop1 (`Fa0`)
- `Fa1/1` → Laptop2 (`Fa0`)
- `Fa0/1` (uplink) → Multilayer Switch0 `Fa0/3`

**VLAN 20 – IT (SW-IT)**
- `Fa1/1` → Laptop3 (`Fa0`)
- `Fa2/1` → Laptop4 (`Fa0`)
- `Fa3/1` → Laptop5 (`Fa0`)
- `Fa0/1` (uplink) → Multilayer Switch0 `Fa0/1`

**VLAN 30 – GUEST (SW-GUEST)**
- `Fa3/1` → Laptop8 (`Fa0`)
- `Fa1/1` → Laptop6 (`Fa0`)
- `Fa2/1` → Laptop7 (`Fa0`)
- `Fa0/1` (uplink) → Multilayer Switch0 `Fa0/2`

All laptops obtain their IP configuration (address, mask, gateway, DNS) dynamically from the central DHCP server, which is configured with a separate address pool for each VLAN.

## How the Topology Works

### 1. VLAN Segmentation

Each department (HR, IT, GUEST) is assigned to its own VLAN on its access switch. This keeps broadcast domains separate: a broadcast generated by a laptop in VLAN 10 (HR) is never seen by hosts in VLAN 20 (IT) or VLAN 30 (GUEST), even though they all share the same physical infrastructure.

### 2. Trunking to the Multilayer Switch

Each access switch (SW-HR, SW-IT, SW-GUEST) is connected to the Multilayer Switch0 through a single uplink port configured as an **802.1Q trunk**. The trunk tags frames with the VLAN ID as they cross the link, allowing a single physical cable to carry traffic for one (or, in a broader design, multiple) VLANs while keeping them logically distinct on both ends.

### 3. Inter-VLAN Routing

Because plain Layer 2 switches cannot route between VLANs, a **Switched Virtual Interface (SVI)** is created on the Multilayer Switch0 for each VLAN (e.g. `interface vlan 10`, `interface vlan 20`, `interface vlan 30`). Each SVI is assigned an IP address that acts as the **default gateway** for the hosts in that VLAN. IP routing is enabled globally on the switch (`ip routing`), which allows it to forward packets between VLAN 10, VLAN 20, and VLAN 30 at Layer 3 — this is what lets, for example, an HR laptop reach the DHCP or DNS server, or (if permitted) a host in another VLAN.

### 4. Centralized DHCP Across VLANs

The DHCP server sits outside all three client VLANs, directly attached to the multilayer switch on the server segment. Because DHCP requests are broadcast (Layer 2) and the server is not on the same VLAN as the clients, the SVI of each VLAN is configured with an **IP helper address** pointing to the DHCP server:

```
interface vlan 10
 ip helper-address 192.168.1.2
!
interface vlan 20
 ip helper-address 192.168.1.2
!
interface vlan 30
 ip helper-address 192.168.1.2
```

This converts the client's DHCP broadcast into a unicast request forwarded to the server, which then replies with an address from the pool configured for that specific VLAN, along with the correct default gateway and DNS server.

### 5. DNS and Web Services

The DNS server resolves the name `www.yourcompany.com` to the Web Server's address (`192.168.1.4`), so that any client — regardless of which VLAN it belongs to — can reach the corporate website by name instead of by IP, as long as inter-VLAN routing and reachability to the server segment are in place.

### 6. Default Gateway and External Connectivity

The Core-Router is the exit point of the whole network. Its `Gig0/0/0` interface, addressed as `192.168.1.1`, is the default gateway for the server segment and represents where the network would connect outward (e.g., toward the Internet or another site) in a real deployment. The Multilayer Switch0 would typically have a default (static) route pointing to the Core-Router for any traffic that isn't destined to one of its directly connected VLANs or the server subnet.

## Functional Summary

| Device | Role | VLAN / Segment | Uplink Port |
|---|---|---|---|
| Core-Router | Network edge / default gateway for server segment | 192.168.1.0/24 | Gig0/0/0 → MLS Fa0/7 |
| Multilayer Switch0 | Inter-VLAN routing, trunk aggregation, DHCP relay | All VLANs + server segment | — |
| DHCP Server | Assigns IPs to VLAN 10, 20, 30 | 192.168.1.0/24 | Fa0 → MLS Fa0/4 |
| DNS Server | Resolves www.yourcompany.com | 192.168.1.0/24 | Fa0 → MLS Fa0/5 |
| Web Server | Hosts corporate website | 192.168.1.0/24 | Fa0 → MLS Fa0/6 |
| SW-HR | Access switch, VLAN 10 – HR | VLAN 10 | Fa0/1 → MLS Fa0/3 |
| SW-IT | Access switch, VLAN 20 – IT | VLAN 20 | Fa0/1 → MLS Fa0/1 |
| SW-GUEST | Access switch, VLAN 30 – GUEST | VLAN 30 | Fa0/1 → MLS Fa0/2 |

Once configured, every laptop automatically receives an address from its department's DHCP scope, resolves internal names through the shared DNS server, and reaches the Web Server and other VLANs solely through the routing performed by the Multilayer Switch0 — while remaining logically isolated from the other departments at Layer 2.
